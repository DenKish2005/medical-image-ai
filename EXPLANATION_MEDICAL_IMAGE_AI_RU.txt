4. ПОДРОБНО: КАК ЗАДЕЙСТВОВАН КАЖДЫЙ DOCX
===============================================================================

4.1. Diagnostic Risk-Constrained Compression

В документе сначала идёт CXR -> E -> F -> compressor C -> bitstream ->
decoder D -> H -> pathology logits. Теперь это поддерживается через
DenseNet121Split + ConditionalFeatureCodec.

Слой можно выбрать из denseblock1, denseblock2, denseblock3. Все значения
split не смешиваются: модель и checkpoint должны соответствовать выбранной
точке. Общая часть сети «на устройстве» (edge) создаёт feature F. Остаток
сети (cloud) принимает восстановленный F и выдаёт disease logits.

Диагностическая функция потерь разделена на:
- masked/weighted BCE для классификации;
- Bernoulli KL distillation между logits teacher/student при temperature;
- MSE-реконструкцию признаков;
- ROI weighted consistency (если на TRAIN доступны lesion bounding boxes);
- оценку битрейта и штраф за превышение target estimate.

Почему Bernoulli KL, а не обычный softmax KL: заболеваний на снимке может
быть несколько одновременно, классы не взаимоисключающие. Softmax
предполагал бы сумму вероятностей равную единице и мог бы искажать
multilabel-предсказания.

Реализован запрет использования тестовых lesion boxes при инференсе:
согласно data.py, boxes читаются только для split=train. В val/test
компрессор видит только свой tensor features и обученные параметры.

Ограничение: risk-aware сохранение очагов ещё не доказано — модель надо
обучить, провести абляции и медицинскую оценку. Возможность передать ROI
loss не означает автоматически высокую lesion sensitivity.

4.2. Uncertainty-Guided Bit Allocation

Созданы два маленьких spatial-head:
- importance head оценивает диагностическую важность позиции feature grid;
- uncertainty head оценивает обучаемый proxy неопределённости.

Для обучения этих головок используются teacher gradient sensitivity и
predictive-entropy gradient sensitivity; для реального inference они уже
не требуют ground truth. В score вычисляется комбинация
alpha * importance + (1-alpha) * uncertainty.

Распределитель распределяет 2, затем 4, затем 8 бит на позицию с учётом
числа латентных каналов и заданного приблизительного бюджета. Доступны
`uniform`, `random`, `saliency`, `uncertainty`, `combined`, чтобы
исследовать вклад каждого компонента, а не просто показывать итог.

Карта глубины передаётся в битстриме и считается в его полном размере.

ВАЖНАЯ НАУЧНАЯ ОГОВОРКА: энтропия прогнозов и её градиент по признакам —
не то же самое, что корректно оценённая эпистемическая неопределённость.
В документе предлагаются MC-dropout/ensemble/calibration. Здесь реализован
воспроизводимый прототип-прокси, а НЕ научно валидированный estimator
uncertainty. Для paper-quality эксперимента нужны настоящие ensemble / MC
статистики, calibration error, шумовые/OOD абляции и сравнение на внешнем
наборе. Иначе нельзя утверждать, что uncertainty-guided метод лучше.

4.3. Single-Model Variable-Rate Feature Codec

Кодек содержит обучаемые Conv2d(1x1) encoder и decoder. В rate_condition
используется rate embedding (FiLM: channel gain и shift). Один и тот же
кодек принимает rate_fraction и на обучении видит разные бюджетные цели
0.50 / 0.25 / 0.10 / 0.05 по отношению к сырым FP16-признакам.

Во время обучения применяется Straight-Through Estimator (STE):
forward имитирует квантование, но backward пропускает градиент к encoder.
FiLM зависит от rate_fraction и в encoder, и в decoder; значение
rate_fraction хранится в заголовке, чтобы декодер применял тот же режим.

Фактический битстрим делает encode_symbols():
- упаковывает квантованные символы с соответствующими 2/4/6/8 бит;
- отдельно кодирует двумерную карту распределения по 2 бита;
- сжимает упакованные данные zlib DEFLATE;
- добавляет magic MFCR, версию, длину заголовка;
- записывает shape [C,H,W], split, rate_id, amax, тип кодека и размеры;
- возвращает реальные bytes, которые decoder может прочитать.

При decode проверяются версия, форма, имя слоя, карты, размеры и
валидность payload. Все эти служебные байты входят в len(message)*8.

Различие принципиальное:
* estimated_bits — дифференцируемая оценка из Laplace-прокси для loss;
* actual_bits — настоящие байты бинарного сообщения, умноженные на 8.

Нельзя назвать экономией фактической полосы одну только меньшую форму
latent: если заголовок, allocation map или кодирование съедают много
байтов, результат budget_met=false должен это показать.

Дополнительно есть отдельный расчёт сетевой задержки с bandwidth,
edge/encode/decode/cloud times, а также p50/p95 и throughput.

Ограничение: zlib/DEFLATE не является обученным entropy coding в смысле
полного варианта из DOCX с arithmetic/ANS/range coder и calibrated entropy
model. Это реально декодируемая и учитываемая по байтам реализация,
но для серьёзной статьи понадобится сравнить её с CompressAI/ANS,
оптимизировать rate proxy и проверить actual-vs-target достижимость.

   сохранил predictions и metrics. Эти тестовые артефакты НЕ входят
   в выдаваемый патч. Синтетические числа AUROC/bitrate не имеют
   никакого медицинского смысла.

D. `compileall` для нового research_compression/ — без синтаксических
   ошибок.

НЕ проверено на живых данных:
- обученная клиническая точность CheXpert/MIMIC-CXR;
- small lesion sensitivity на VinDr-CXR/CheXlocalize;
- реальное сравнение всех ablations при matched achieved rate;

  недоступных ноутбуках;

===============================================================================
9. ПОЧЕМУ Я НЕ ПЕРЕПИСАЛ СУЩЕСТВУЮЩИЕ NOTEBOOKS
===============================================================================

Это решение обусловлено не экономией сил, а совместимостью:

(1) Большие notebook файлы содержат результаты ячеек и могут быть
    частично недоступны по коннектору. Автоматическая полная замена
    приведёт к удалению вывода или потере пользовательских изменений.

(2) Основной доступный notebook работает на caption/report generation,
    а в DOCX основная первичная метрика — CXR disease diagnosis AUROC.
    Без новой разметки нельзя корректно встроить loss как простой
    copy-paste на существующий training loop BLIP.

(3) R2Gen и DenseNet/BLIP имеют разные tensor shapes, pretrained weights,
    split layer и token semantics. Подстановка неподходящего codec
    может разрушить результаты, даже если Python не выбрасывает ошибку.

(4) Отдельный модуль с именованным adapter позволяет сначала проверить
    shape и обучить совместимый codec, а уже потом (при необходимости)
    протестировать R2Gen report-generation на тех же изображениях.

Итог: новая инфраструктура интегрирована в папку репозитория и имеет
механизм подключения к его моделям, но не выдаётся за уже завершённую
интеграцию внутрь всех исходных экспериментов и notebooks.

10. ЧТО НУЖНО ДОРАБОТАТЬ ДЛЯ MICCAI 2027
===============================================================================

Первая очередь:
- собрать настоящий patient-level CXR dataset с подтверждёнными метками;
- обучить надёжный uncompressed baseline и проверить AUROC по болезням;
- протестировать несколько split points и 2/4/6/8 uniform quantization;
- зафиксировать compute budget и 3 random seeds;
- на каждом target сравнить matched ACHIEVED rate, а не просто ratio.

Вторая очередь:
- обучить 4 независимых fixed-rate compressors для честного сравнения
  с одной variable-rate моделью;
- заменить градиентный uncertainty proxy на проверенную ensemble или
  MC-dropout оценку и провести calibration OOD/clean/noisy ablations;
- добавить PCA/linear baseline и (при возможности) learned ANS/range coder;
- экспериментально подобрать lambda_rate, ограничения на реальный поток,
  а не объявлять approximate greedy гарантированным budget solver;
- для VinDr-CXR внедрить small-lesion sensitivity и bbox localization;
- учесть all-edge и full-image-cloud alternatives в сравнении latency;
- провести врачебный review опасных false negatives/false positives.

Перед публикацией обязательно: основная гипотеза, доверительные интервалы,
коррекция множественных проверок, отчёт по failed/negative results,
стратификация по размерам очагов, полный reproducibility bundle.
